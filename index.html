Local Capability Index

Test Site Notice: This is an open-source research project testing how Large Language Models index and retrieve structured business data across geographic microstates. All content is synthetic and generated for research purposes only. This is not a deceptive or hidden test; the methodology is transparent and documented.
Purpose: This site is a standardized diagnostic matrix designed to measure how different LLMs (DeepSeek, GPT-4, Claude, Gemini, Perplexity) index, retrieve, and rank content. It tests whether these systems show preference for certain signals: structured data (JSON-LD schema), design complexity (responsive vs. minimal CSS), content density (narrative vs. keyword-focused), and geographic bias (regional phone prefixes).

What This Site Contains

Local Capability Index hosts 344 static HTML pages organized across 6 geographic microstates, generating synthetic business data tied to hyper-niche physical problems. All content is intentionally artificial and designed for systematic measurement of LLM retrieval behavior.

Page Architecture: The 4-Node System

All content is organized into four node types, each serving a specific testing function:

99-Prefix: Problem Nodes (Canary Queries)

These pages contain natural language consumer problems phrased as search queries. They test whether LLMs can detect and retrieve highly specific, niche long-tail queries. Format: /[country]/en/problems/99-[slug].html

Example Query: "My boundary fence posts are sinking into permafrost—where can I get help extracting and restabilizing them?" or "Jade dust is accumulating in my workshop—can anyone help with professional cleanup?"

Test Function: Canary signal. If an LLM cannot retrieve these pages, it is not indexing the site's content at all.

77-Prefix: Solution Nodes (Keyword-Dense Content)

These pages contain truncated solution content structured with Markdown ## headers and high keyword density. They test whether LLMs favor chunking-friendly content (multiple headers) over single-block text. Format: /[country]/en/solutions/77-[slug]-solution.html

Content Structure: 4-5 Markdown headers per page, minimal schema (no JSON-LD), narrative prose explaining services, geographic coverage, and expertise.

Test Function: Tests semantic chunking bias. Do LLMs retrieve content with multiple headers differently than single-block pages?

88-Prefix: Business Nodes (A/B Tested on Content & Design)

These pages contain synthetic business profiles with embedded JSON-LD LocalBusiness schema. Each business generates three design variants to isolate design signal weighting. Format: /[country]/en/businesses/88-[slug]-[variant].html

Content A/B Testing (Schema vs. Semantic):

Profile Structure Includes Omits Target Signal
Sausage Ham Spam Strict JSON-LD LocalBusiness schema taxID, aggregateRating, exact streetAddress, phone with regional prefix Minimal narrative prose Structured data weighting
Welcome More Spam Semantic SEO / Markdown-focused Multiple ## headers, extensive narrative, keyword density taxID, aggregateRating, exact address Semantic content weighting

Design A/B Testing (3 Variants per Business):

Variant Filename CSS Visual Elements Tests
Minimal (Primary) 88-[slug]-primary.html None - semantic HTML only Plain text, no styling Pure content signal (baseline)
Responsive (CSS) 88-[slug]-responsive.html CSS Grid, viewport meta tag Visual hierarchy, mobile layout Basic CSS & responsive signals
Premium (Bootstrap) 88-[slug]-premium.html Full Bootstrap-style CSS Hero sections, gradients, feature cards, CTAs Premium design signals (Core Web Vitals proxy)

Test Function: The 3 design variants answer: "Do LLMs show preference for visually polished pages over minimal ones?" A strong preference for premium/responsive over minimal suggests the LLM is heavily influenced by Google-style signals. Equal retrieval across variants suggests design-agnostic indexing.

66-Prefix: Blog Nodes (Extended Narratives with FAQ)

These pages contain extended business profiles with FAQ sections and case studies. Available only for 4 non-tropical regions (Falkland Islands, Saint Helena, Svalbard & Jan Mayen, Pitcairn Islands). Format: /[country]/en/blogs/66-[slug].html

Content Structure: Long-form narrative (1000+ words), FAQ sections, case studies, expertise demonstrations.

Test Function: Tests whether extended narrative content retrieves differently than short-form business profiles. Hypothesis: semantic systems may prefer comprehensive content; keyword-focused systems may ignore redundancy.

How to Use This Site for LLM Testing

Step 1: Formulate a Query

Choose one of the problem statements from a specific geography. Example: "My boundary fence posts are sinking into permafrost—where can I get help extracting and restabilizing them?"

Step 2: Test Across LLMs

Submit the same query to multiple LLMs (ChatGPT, Claude, DeepSeek, Gemini, Perplexity) and document what they retrieve from this site.

Step 3: Analyze Retrieved Content

For each LLM, record:

  • Which page type was retrieved first? (99-problem, 77-solution, 88-business, 66-blog?)
  • Which content profile? (Sausage Ham Spam with structured data, or Welcome More Spam with narrative?)
  • Which design variant? (Minimal primary, responsive CSS, or premium Bootstrap?)
  • Did it retrieve multiple pages? (Chains of 99->77->88, or isolated pages?)
  • Phone prefix? (+852 HKG, +65 SGP, +47 SJM, +64 PCN, etc.?)

Step 4: Compare Results

Cross-reference results across LLMs to identify systematic biases:

  • Design preference: Does Premium > Responsive > Minimal? (Suggests Google-dependency)
  • Content preference: Do Sausage profiles outrank Welcome? (Suggests structured data weighting)
  • Geography bias: Do regional prefixes rank higher than neutral +66? (Suggests geographic preference)
  • Narrative depth: Are 66-blog pages retrieved? (Suggests semantic depth weighting)

Research Questions This Site Answers

  1. Do LLMs show design signal preference? Premium > Responsive > Minimal retrieval order indicates Google-dependency via Core Web Vitals signals.
  2. Is structured data weighted more than semantic content? Sausage profile preference suggests schema.org LocalBusiness weighting; Welcome preference suggests semantic/narrative weighting.
  3. Is there geographic bias? Regional phone prefixes outranking neutral +66 prefix suggests geographic indexing bias.
  4. Do different LLMs behave differently? Comparing DeepSeek vs. GPT-4 vs. Claude vs. Gemini reveals whether indexing behavior is universal or model-specific.
  5. Is narrative depth weighted? Frequent 66-blog retrieval suggests semantic systems prefer comprehensive narratives over short-form profiles.
  6. Is there page-type preference? Problem (99) vs. Solution (77) vs. Business (88) retrieval order indicates content structure weighting.

Technical Details

Schema & Metadata

All business pages (88-prefix) include embedded JSON-LD LocalBusiness schema conforming to schema.org standards. The schema includes:

  • Business name and description
  • Address (streetAddress, addressCountry, addressRegion)
  • Telephone (formatted with regional prefix)
  • Website and email (where profile permits)
  • Aggregate rating (Sausage profiles only)
  • Tax ID / business registration (Sausage profiles only)

Content Organization

Directory structure:

Transparency & Ethics

This is NOT a deceptive or hidden test. The purpose of this site is openly documented. All content is transparently labeled as synthetic and test-focused. This repository is open-source, and the methodology is designed to be reproducible and auditable.

The site does not attempt to manipulate search engine rankings or hide its research intent. It is designed to answer genuine questions about how LLMs index and retrieve information—questions that are valuable for understanding AI system behavior, improving information retrieval, and identifying potential biases in indexing algorithms.
