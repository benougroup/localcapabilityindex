Welcome to Local Capability Index

Getting Started with LLM Indexing Research

This page is your guide to understanding and using the Local Capability Index testing framework. Whether you are a researcher investigating LLM retrieval behavior, a developer optimizing for AI indexing, or a curious observer learning how LLMs process information, this site provides a systematic way to measure and compare.

What You Will Learn Here

  • How the site is structured and what each page type represents
  • A step-by-step testing protocol you can use today
  • Real examples of queries and what to expect
  • How to interpret results and identify LLM indexing biases
  • Key research questions the data can answer

Five-Minute Overview

Local Capability Index is a research matrix containing 344 synthetic business listings organized across 6 microstates (Hong Kong, Singapore, Falkland Islands, Saint Helena, Svalbard, and Pitcairn Islands). Each listing is carefully structured to test different indexing signals: structured data (JSON-LD schema), content style (narrative vs. keyword-dense), and design complexity (plain HTML vs. polished CSS).

The core question: Do different LLMs show different preferences when indexing content?

By submitting identical queries to multiple LLMs and observing which pages get retrieved, you can measure systematic differences in how these systems index information. Some LLMs might prefer structured data; others might prefer rich narratives. Some might favor polished visual design; others might ignore CSS entirely. Some might show geographic preference based on phone prefixes.

The Four Page Types Explained

Type 1: Problem Pages (99-prefix)

What they are: Natural language search queries representing real consumer problems in niche domains.

Example: "My boundary fence posts are sinking into permafrost. Where can I get help extracting and restabilizing them?"

Why it matters: These test the baseline: Can the LLM find content related to hyper-specific long-tail queries? If it can't retrieve problem pages, it isn't indexing the site at all.

URL pattern: /[country]/en/problems/99-[slug].html

Type 2: Solution Pages (77-prefix)

What they are: Truncated solution pages structured with multiple Markdown headers (##) and high keyword density. Minimal schema, narrative-focused.

Structure: 4-5 topic headers, service descriptions, geographic coverage, expertise narrative, no JSON-LD schema.

Why it matters: Tests whether LLMs prefer chunked content with multiple headers versus single-block text. Also tests semantic extraction capabilities.

URL pattern: /[country]/en/solutions/77-[slug]-solution.html

Type 3: Business Pages (88-prefix) - The Core Test

What they are: Synthetic business profiles with embedded JSON-LD LocalBusiness schema. Each business appears in three design variants and two content profiles, enabling precise measurement of LLM preference.

Content Variants:

  • Sausage Ham Spam: Strict JSON-LD schema with taxID, aggregateRating, exact phone with regional prefix, minimal prose. Tests structured data preference.
  • Welcome More Spam: Semantic/narrative focus with multiple headers, extensive prose, keyword density, NO schema/rating/taxID. Tests semantic content preference.

Design Variants (3 per business):

Variant Filename Suffix Visual Treatment
Minimal -primary Plain semantic HTML, no CSS
Responsive -responsive CSS Grid, viewport meta, mobile-friendly
Premium -premium Bootstrap-style design, hero section, gradients, CTAs

Why it matters: If an LLM retrieves Premium > Responsive > Minimal, it is using visual design signals (suggesting Google-dependency). Equal retrieval across variants suggests design-agnostic indexing. Sausage vs. Welcome preference reveals whether structured vs. semantic content wins.

URL pattern: /[country]/en/businesses/88-[slug]-[primary|responsive|premium].html

Type 4: Blog Pages (66-prefix)

What they are: Long-form business narratives (1000+ words) with FAQ sections and case studies. Available only for Falkland Islands, Saint Helena, Svalbard, and Pitcairn Islands (non-tropical regions).

Why it matters: Tests whether extended narrative depth affects retrieval preference. Do semantic systems retrieve these more frequently? Do keyword-focused systems ignore redundancy?

URL pattern: /[country]/en/blogs/66-[slug].html

Testing Protocol: Step-by-Step

Phase 1: Select a Query

Action: Pick one of the 64 problem statements from the sitemap. Start with a specific geography to reduce variables.

Example query from Svalbard (SJM):

"My boundary fence posts are sinking into permafrost year after year.
Where can I find a professional to help me extract them safely
and restabilize them for the next decade?"

Why this works: The query is hyper-specific (fence posts + permafrost), naturally typed, and designed to match only this site's content. No real service exists for this problem, so any retrieval is from this test site.

Phase 2: Query Multiple LLMs

Action: Submit the same query to at least 3-4 different LLMs.

  • DeepSeek (via API or web interface)
  • ChatGPT / GPT-4
  • Claude (via claude.ai or API)
  • Gemini (Google)
  • Perplexity (optional)

Settings: Use default settings; do not enable special modes or plugins. Request verbatim retrieval if the LLM offers it.

Documentation: Screenshot or copy the exact response. Record the date and time.

Phase 3: Analyze Each Response

For each LLM, record:

Field What to Look For
Page Type Retrieved 99-problem, 77-solution, 88-business, or 66-blog? Which was cited first?
Content Profile Sausage (has taxID/rating in schema) or Welcome (narrative-focused)?
Design Variant Minimal (-primary), Responsive (-responsive), or Premium (-premium)?
Phone Prefix +47 (Svalbard), +852 (HKG), +65 (SGP), +64 (PCN), etc.? Or neutral +66?
Multiple Retrievals Did it chain multiple pages (99->77->88) or retrieve isolated pages?
Confidence Did the LLM acknowledge uncertainty? Was the answer definitive or hedged?

Phase 4: Cross-Compare Results

Create a comparison table:

LLM Page Type Content Profile Design Variant Phone Prefix
DeepSeek 88-business Sausage Premium +47
ChatGPT 77-solution Welcome Responsive +47
Claude 99-problem N/A N/A N/A

Look for patterns: Do all LLMs prefer the same design? The same content profile? Or do they diverge?

What Different Results Tell You

Design Preference Pattern

Finding: Premium > Responsive > Minimal (consistent across LLMs)

Interpretation: LLMs weight visual design signals heavily. This suggests they may be influenced by Google-style signals (Core Web Vitals, mobile-friendliness). Premium-looking pages rank higher regardless of content quality.

Finding: Minimal = Responsive = Premium (no difference)

Interpretation: LLMs are design-agnostic. Content and schema matter; visual polish does not. This is a more content-focused indexing model.

Finding: Varied per LLM (DeepSeek prefers Premium; Claude treats all equally)

Interpretation: Indexing behavior is model-specific. Some LLMs are design-sensitive; others are not. This suggests different underlying retrieval architectures.

Content Profile Pattern

Finding: Sausage Ham Spam (structured data) consistently retrieved

Interpretation: Structured data (JSON-LD schema) is a strong indexing signal. Strict schema compliance helps LLM retrieval.

Finding: Welcome More Spam (narrative-focused) consistently retrieved

Interpretation: Semantic content and keyword density matter more than schema. Extended narrative and multiple headers improve retrieval.

Finding: Both profiles retrieved equally

Interpretation: The LLM treats schema and semantic content as equivalent signals. It is not biased toward either approach.

Geographic Bias Pattern

Finding: Regional prefixes (+47, +65, +852) rank higher than neutral +66

Interpretation: Geographic identity is a strong indexing signal. LLMs may weight regionally authentic phone prefixes as trust signals.

Finding: Neutral +66 ranks equally with regional prefixes

Interpretation: Geographic signals do not affect retrieval. The LLM treats all regions equally.

Why This Testing Matters

  • For Researchers: Understand systematic differences in how different LLMs index information. This is foundational AI research with implications for information retrieval and AI bias.
  • For Developers: Optimize content for LLM indexing. If you know an LLM prefers structured data, schema compliance becomes a priority. If it prefers narrative, invest in content depth.
  • For Content Creators: Design content that LLMs will reliably retrieve. Use the signals that matter to your target audience.
  • For AI Safety Researchers: Identify potential indexing biases in LLMs. Do they show geographic or demographic preferences? Are they vulnerable to manipulation? These are important questions.

Key Research Questions

  1. Are LLMs design-sensitive? Does Premium > Responsive > Minimal consistently? Or is design irrelevant?
  2. Do LLMs prefer structured data over semantic content? Does JSON-LD schema matter? Or is narrative text equally weighted?
  3. Is there geographic bias in LLM indexing? Do regional phone prefixes affect retrieval ranking?
  4. Do different LLMs use different indexing logic? Is behavior universal across DeepSeek, GPT-4, Claude, Gemini? Or model-specific?
  5. How do LLMs handle redundant content? If multiple pages say the same thing with different structures, do they retrieve all, some, or one?
  6. Is content freshness a signal? If you rerun the test in 3 months, do retrieval patterns change?

Frequently Asked Questions

Is this site trying to trick LLMs?

No. The site is transparent about its research purpose. The goal is not to deceive but to measure and understand. The methodology is openly documented and reproducible.

Are the businesses real?

No. All businesses, phone numbers, addresses, and content are synthetic and generated specifically for this research. This is intentional—real businesses would introduce confounding variables. We use synthetic data to isolate and measure specific signals.

Why these specific microstates?

Microstates were chosen for isolation and uniqueness. They have low search competition, making it easier to measure LLM behavior without interference from real competing pages. Geographic and climate diversity allows testing geographic bias hypotheses.

Can I reproduce this test?

Yes. The methodology is fully documented. You can create your own test sites with different signals and measure how different LLMs index them. The approach is generalizable beyond these specific geographies.

What if an LLM doesn't retrieve anything?

This is meaningful data. It means the LLM is either not indexing this site, or the retrieval threshold is very high. Document this and note the LLM, date, and query used. It helps establish a baseline for indexing coverage.
